H52 — format and uniqueness audit

Every clause of the published format was checked by re-reading the written GeoTIFF: True single band, float32, 12,279,160 finite cells, values in [0.0, 1.0], 0 values outside [0, 1], 0 non-zero cells outside the footprint, 0 dots on the provided catalogue, and no large-negative nodata sentinel (the failure mode behind the earlier portal range error).

Uniqueness against 16 prior artifacts (each re-fetched from its publishing repository and verified by cell count before comparison): the worst prior covers 42.8% of H52's dots within 2 px, so 57.2% of the dots are at least 300 m from any prior dot, and 87.8% are outside the union of all prior supports. The artifact compared against itself is excluded by path, by SHA-256 and by identical-support detection.

Uniqueness

Block-level Jaccard against 50 frozen prior artifacts: worst case 0.6597 against gems16-h16-1-topo-geophys-baseline-ridges-20260930-df20f65e-nan.tif. That number is only meaningful next to its null distribution — among genuinely independent prior artifacts the same statistic has median 0.8252 and maximum 1.0000, and this file sits below that median. The audited statement is narrower: a new sha256, no prior raster read into the belief field, and 2.72% exact-pixel overlap with the only prior submission available locally (evidence/uniqueness_h51.json).
