Executive summary — and exactly how to submit

Executive summary

  1. The file. One GeoTIFF, gems50-seislin-44709-20261006T2041Z-79e260ae.tif, single band, float32, EPSG:32611, 100 m, 3730×3292, values exactly 0 and 1, NaN outside the study footprint, 44,709 positive pixels. Minimum 0.0, maximum 1.0.
  2. Why it can score. The official metric is DTI = T/(0.2(T+F) + 0.8G) with a 300 m triangular kernel; because T + FN = |G| exactly, the denominator is 0.8G + 0.2(T+F). A dot pays whenever its kernel credit exceeds 0.2·score — so the optimum is a binary support at ≈300 m spacing placed where extra faults are most likely, not a probability map. The file is emitted on that rule.
  3. Where the dots are. Dominantly on 1 m-LiDAR scarp dipoles that line up in chains (validated: 2.2× the matched random control on the off-catalogue frame), with a low-weight hedge on seismicity corridors.
  4. What failed. The seismicity-lineament corridors did not beat smoothed earthquake density at equal dot budget (0.0015–0.0034 vs 0.0016–0.0043). Reported as falsified; kept only as a hedge.
  5. Uniqueness. Checked against all 50 prior submissions on this grid: no identical file, ≤ 0.36 overlap, ≥ 47 % novel pixels. Automatic, no manual check.

Submit it — step by step

  1. Open the competition page: drivendata.org/competitions/306/competition-doe-gems and sign in.
  2. If the competition does not yet appear on your account, press Join Competition (top right) and accept the rules.
  3. Go to the Submissions tab (the same tab that shows the public leaderboard).
  4. Press Upload submission / Choose file and select gems50-seislin-44709-20261006T2041Z-79e260ae.tif — or the .zip if the form asks for one; it contains exactly one GeoTIFF.
  5. Paste the one-line note from the top of the README into the description field if one is offered.
  6. Submit, wait for the score to appear on the public leaderboard, and record it in registry/leaderboard_history.jsonl (the site's feed is regenerated from that file by scripts/build_site.py).

The upload is one file and one click; nothing else is required. The submission is formatted to satisfy every rule stated on the problem page.
