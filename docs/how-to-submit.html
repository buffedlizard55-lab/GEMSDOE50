Built as specified: 63,081 screened USGS ComCat earthquakes, declustered with the Zaliapin–Ben-Zion nearest-neighbour method (12,450 background events kept), a 2-D triangle test (my unverified adaptation of the Ouillon–Sornette 3-D tetrahedron test), local 2-D covariance with location-error removal, corridors as wide as the catalogue location error plus up-dip copies, and dots snapped to the H57 ridge. Result: only 31 lineations and 326 dots; holdout DTI 0.0002, credit/dot 0.0232 versus 0.1267 for random dots. On withheld catalogue faults the corridors lose to smoothed density (0.0007 vs 0.0093). Loosening every screen (up to 1,034 lineations) never lifts that ratio above 0.97. Exactly how to submit

  1. Download gemsdoe50-h57-scarpstep-80000-20261007T1830Z-allfinite.tif (or the .zip; the portal accepts a .tif or a .zip holding one GeoTIFF).
  2. Check the bytes (optional but recommended). The SHA-256 must be 8027c4e9fe0f789e2d7180a7ccc031abec90b391cf9e42ebcc125752af9fb696.
    macOS/Linux: shasum -a 256 gemsdoe50-h57-scarpstep-80000-20261007T1830Z-allfinite.tif · Windows PowerShell: Get-FileHash gemsdoe50-h57-scarpstep-80000-20261007T1830Z-allfinite.tif -Algorithm SHA256
  3. Open the DOE GEMS competition page, sign in, and go to the submissions tab. Read the submission-format page once: single-band GeoTIFF, same CRS (EPSG:32611), shape and geotransform as the training data, values between 0 and 1.
  4. Upload the file. If the form asks for a name, use GEMSDOE50-H57-SCARPSTEP.
  5. Paste the note (optional field): H57 stratified LiDAR-scarp + topographic-step dot emitter; every dot is >=300 m from the given catalogue and >=300 m from every other dot; research model, not organizer-scored.
  6. Submit and record the public score and the submission time in registry/submissions.json so later sessions can calibrate against a real organizer number.

If the portal says “Predicted values must be in range [0, 1]”

That message appears when any cell the validator reads is outside [0, 1] — and a NaN counts, because NaN ≤ 1 is false. This file has no NaN, no nodata sentinel and only the values 0 and 1 in all 12,279,160 cells, so the error cannot come from it. If you see it anyway, you uploaded a different file: compare the SHA-256 above. Do not upload the -nan or older files.

Limits to keep in mind
